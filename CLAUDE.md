# TugOfWar2

Мобільна 2D tug of war стратегія на Unity, де гравець викликає цілі загони, а не окремих юнітів.

## Архітектура (принципи)
- Дані окремо від коду: характеристики загонів у ScriptableObject (D-004).
- Загін це логічний об'єкт; солдати лише візуал (D-001).
- Маленькі скрипти з однією відповідальністю; залежності явні, без пошуку об'єктів по імені.
- Нова система = короткий опис у `Docs/` перед кодом.

## Структура проєкту
```
Assets/_Project/
  Scripts/      код, по папках систем (Battle, Squads, Economy, UI, Meta)
  Data/         ScriptableObject-и (типи загонів, баланс)
  Prefabs/
  Scenes/
  Art/  Audio/
```

## Робота з Unity Editor через CLI
Unity CLI (`unity`) встановлений, а в проєкті є пакет Pipeline, тож відкритим редактором можна керувати напряму.
Скіл `unity-cli` містить повний довідник.
- `unity status`: чи підключений редактор (стан `ready`). Після перекомпіляції сервер ненадовго зникає
  (domain reload); чекай через `unity status --until-ready`.
- `unity recompile`: перекомпілювати й отримати помилки та попередження.
- `unity command test run --mode editor --result-only`: запустити EditMode-тести.
- `unity command script eval_file --file <шлях до .cs у scratchpad> --result-only`: виконати C# у редакторі.
  Так створюються ассети і об'єкти сцени (через `SerializedObject`, `AssetDatabase`).
- `unity command` без аргументів: список усіх команд (сцени, GameObject-и, Play mode, Console, скріншоти).
- Play mode: `unity command editor.playmode start|stop`. Скріншот: `unity command capture game_view --source camera
  --width 540 --height 960 --save_path <шлях>`. Шлях рахується від `Assets/`, тож файл стає ассетом:
  після перегляду видаляй його через `AssetDatabase.DeleteAsset`.
- У `eval_file` не пиши `using`: `UnityEngine` і `UnityEditor` вже підключені (`Object` пиши як `UnityEngine.Object`).
- Якщо задаєш ассету значення, що дорівнює значенню за замовчуванням, Unity не зберігає файл; викликай
  `EditorUtility.SetDirty` + `AssetDatabase.SaveAssetIfDirty`.
- Не правити YAML `.unity` / `.prefab` / `.asset` руками, поки редактор доступний.
- Перевіряй сам усе, що можна перевірити через CLI (компіляція, тести, Console, Play mode); Влада проси
  перевірити те, що треба побачити очима або відчути в грі.

## Робочий процес
- Кожна задача в окремій гілці, зміни через PR.
- Не комить згенеровані Unity папки (`Library/`, `Temp/`, `Logs/`, `Obj/`, `Build/`).
